01 · Scope

What the 26 Oct call asked for

  • Four files due Tue 27 Oct: the MoE config, the config check, the harness and plan_v0. The submission is a skeleton: keys and structure matter now; values come later from TSAI (Rohan).
  • Each person pushes their own code under their own folder. The team then cherry-picks the best parts into the skeleton for the main ERA-V5 repo.
  • Known gaps in every config: the data-mixture weights and the distributed parameters (dp, tp, pp). SmolLM3 and nanotron are the reference.
  • Seed 1234: two runs must give the same loss at every step.

How this folder closes both gaps

Data weighting uses SmolLM3-style data_stages: stable → stage2 → anneal at 0 / 0.73 / 0.82 of the steps.

The parallelism block uses nanotron ParallelismArgs names:

dptppppp_enginetp_modezero_stagerecompute_layerexpert_parallel_size
Both run on real hardware.
02 · Design

Architecture at a glance

TokensBrahmicTokenizer-131K (pinned sha), EOS id 36
EmbedKronecker codec (char 256 × pos 32) → trainable projection
AttentionGQA, QK-norm, RoPE θ=50k, SDPA (math backend)
FFNSwiGLU, or MoE: sigmoid router + aux-free bias, dropless
HeadUntied, CE + z-loss 1e-4, fp32
OptimMuon on 2D weights and expert slices; AdamW elsewhere; WSD 2% / 10%

Config

  • configs/config_v0.yaml: every leaf has a # source comment citing the KE code / arXiv 2605.29459, lessons, an Admin ruling or SmolLM3. Sizes are open_keys.
  • harness/check_config.py: 0 errors, 15 open. Every small config: 0 errors, 1 open (the KE2 shape from G4).
  • Small configs extends: a parent with deep merge. configs/small/t4_moe.yaml is the G6 file.

Harness

torchrun harness/train.py --config C --out DIR [--set k=v]
  • A batch depends only on (seed, step), never on the layout, so DP, TP and PP see identical data.
  • Outputs: losses.tsv (exact repr), metrics.jsonl with the six G8 names, checkpoints. On NaN: NAN_REPORT.json plus the resume command.

Read with care

This is one seed and 1,000 steps on about 9M tokens. The gaps are small (≤ 0.033 nats) but consistent from about step 250 onward. Every MoE arm beats dense. The shared expert with top-1 and the 8-expert top-2 arm lead. The fine-grained arm with 16 experts and top-4 balances best but is 2.7× slower on T4, because the reference expert loop doesn't fuse. With load balancing turned off, routing collapses early (dead experts from step 34, up to 7 in one step) but recovers, and its CE is within noise of the balanced arm, so balancing is a stability guard here, not a loss win.

Failed to broadcast an int16 length buffer. Now stored as int64.
